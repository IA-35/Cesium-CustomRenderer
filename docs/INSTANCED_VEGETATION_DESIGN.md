# CCR 实例化网格与植被功能设计

## 0. 2026-09-18 输入确认与修订

- 固定树木点位来自 `Geo-Scatter_Export_geographic_positions_with_type.json`：WGS84，经纬度顺序为 `[longitude, latitude]`，共 720 株；`松柏` 112、`松树` 380、`松树01` 228。点位唯一且均为有限数值，覆盖约 983×910 米。
- 三个真实 GLB 为 `松树02b_LOD.glb`、`松树02c_LOD.glb`、`松树02i_LOD.glb`。每个文件包含命名稳定的 `LOD0`–`LOD3` 四套网格、树干 OPAQUE primitive 和叶片 MASK primitive。
- 默认场景同时挂载四级 LOD，不能直接作为单棵树加载，否则四套网格会重叠。资产准备阶段必须生成四个互斥的 LOD 描述，同时共享同一份几何 buffer 与叶片贴图。
- 首期以固定点位树木为唯一业务输入，不在同一批实现面状草地散布。类型映射集中配置，初始映射为 `松柏→02b`、`松树→02c`、`松树01→02i`。
- LOD 由原草案的两级改为四级；同一空间批次在所有 CCR pass 中使用同一级，按未抖动相机投影尺寸和滞回切换。
- 点位没有高度与朝向。加载时优先调用 Cesium 场景贴地接口批量取得校园地面高度；失败时使用数据原点的 ENU 平面并报告 fallback。朝向和轻微尺度变化由稳定对象名哈希生成，不改变道路规则间距。

用户确认规模：常态实际加载不超过 5,000 株，全场景上限约 10,000 株。以桌面校园场景为设计假设，不承诺在未指定显卡和模型复杂度时达到固定帧率。

## 1. 结论与范围

推荐新增 `CCR.createInstancedMeshCollection`，底层复用 Cesium 1.143 的 glTF `EXT_mesh_gpu_instancing`，按空间块、原型、LOD 和材质兼容性组织批次。实例化负责高效重复绘制；程序化网格负责提供原型几何，两者共用同一条渲染路径。

首期服务静态树木、灌木和成簇草丛：批量摆放、平移/旋转/缩放、批次重建、两级 LOD、可见性与资源管理、PBR/MASK、阴影及 CCR 通道兼容。保留业务 ID，但逐株拾取作为后续小阶段，不把 ID 数据存在误报为 GPU 拾取已经可用。

首期不建设大范围 3D Tiles 流式系统，不做每株骨骼动画、风动画、每帧更新所有实例矩阵、实时拓扑编辑、多光源或新的抗锯齿算法。第三档远景代理只在两级 LOD 不能达标时增加。

## 2. 现有证据与复用点

- 独立工程基线为 `b2b182e`，源码入口 `src/index.js` 当前没有实例化集合接口。
- 已安装引擎 `Model/InstancingPipelineStage.js` 生产实例属性；`Model/ModelDrawCommands.js` 把 `instanceCount` 写入 DrawCommand，使用批次包围体。
- `src/channels/MaterialChannels143.js` 通过 shallowClone 保留原绘制参数；`materialShader143.js` 识别 Model 标准 PBR 和 MASK。存在兼容基础，但没有本功能真实 GPU 测试，不能直接宣称已兼容。
- `src/shadows/ShadowReceiver143.js` 同样克隆源命令；`ShadowCache.js` 签名包含 instanceCount，但明确要求实例缓冲不可变或主动失效。
- `src/shadows/CasterCommands143.js` 的光照视角补选针对 updateForPass；普通 Model 不能直接假定具有该入口。
- `src/environment/FoliageMask143.js` 只修复旧 `SM_NH_Shu` 资源的 alpha mip 问题，不是通用植被材质系统。
- `src/antialiasing/TaaPass143.js` 明确无动态物体 velocity/reactive mask，静态几何才可精确重投影。
- 复用 `RenderProfiler143` / `GpuTimer` 测量提交数量和 GPU 时间；已有各 pass 时间轮换采样，不可相加伪造一帧总 GPU 时间。

## 3. 路线比较

| 路线 | 优点 | 成本和限制 | 决策 |
| --- | --- | --- | --- |
| 原生 glTF GPU 实例化 + CCR 批次管理 | 复用 Model/PBR/阴影派生命令；开发范围可控 | 实例 TRS 缺少公开的高频修改契约，修改需重建小批次；块内不能假定逐株剔除 | 首选 |
| 自定义 instanced DrawCommand | 能自行管理可写实例缓冲与绘制策略 | 需额外适配地球精度、材质、阴影、MRT、拾取和生命周期，升级维护成本高 | 仅在实测证明原生路径不满足必要需求时评估 |
| 3D Tiles 1.1 实例化瓦片 | 原生层级选择、加载与缓存管理 | 需要数据生产与瓦片层级；对 5k 常态规模不必作为首期依赖 | 将来扩展到大范围数据时再引入 |

`GeometryInstance` 是 Cesium Primitive 的几何批处理接口，不能仅凭名称当作任意 GLB 的共享 GPU 实例化。程序生成一棵树再复制顶点 5,000 次，也不等同于共享网格实例化。

## 4. 数据与坐标契约

一个集合包含原型表和实例表：

- 原型：稳定 prototypeId、一个或两个 LOD 资源、米制尺寸、原点位于植株底部、标准 PBR 材质。
- 实例：稳定业务 id、prototypeId、位置、四元数旋转、正数缩放。
- 首期实例颜色变化通过少量原型材质变体实现；不假定任意 `_COLOR` 实例属性可自动参与 Cesium PBR 着色。
- CPU 接受世界坐标或显式带原点的 ENU 坐标，两种输入不能隐式混用。经纬度辅助入口使用角度和椭球高米，必须在契约中声明高度基准。
- 每个块使用自己的双精度世界变换矩阵，GPU 实例平移使用块局部 float32。glTF 的 Y-up 与 Cesium ENU/Z-up 必须显式转换；测试覆盖旋转原型节点、多子网格、块边界和非等比缩放。
- 树根高度由已有地形/校园地面数据一次性批量采样并缓存。对校园模型地面不能误用地形椭球高；样本未就绪时报告未定位，不默认填 0 把树放入地下。

资产准备复用 glTF Transform 的读取、去重、节点变换整理和扩展写入能力，不另写通用 GLB/Draco 解码器。首期工具把来源 GLB 整理成可实例化的静态原型 `.gltf`、共享网格/纹理资源及元信息；原件保留。多节点原型需烘焙正确的节点变换或生成一致的子网格实例变换，不把同一 TRS 随意套到任意层级节点。

运行时从规范原型生成每批 glTF 描述和实例属性缓冲，通过公开 `Model.fromGltfAsync({ url })` 加载生成的资源 URL。避免依赖未公开的 `options.gltf`，不把 5k 个 Model 伪装成一个集合。共享几何、纹理引用保持稳定 URL，实例缓冲按批次独立；跨 Model 的 GPU 资源复用程度须实测，不能把 HTTP 缓存命中当作显存只占一份。

生成描述优先引用共享外部资源，避免为每批嵌入一份大 GLB。Blob URL、加载中的资源和失败资源由集合持有到加载完成/销毁，避免提前回收导致间歇性加载失败。准备工具只进入开发工具链，不增加普通 CCR 页面不需要的资产转换依赖。

## 5. 批次、LOD 与性能策略

初始调参起点为 64–128 米空间格、每批最多 128–256 株；由密度、树种数量和场景跨度实测确定，不能硬编码成固定性能保证。稀疏块可保留较小批次，不能为凑数量把远隔的树并成跨校园包围体。

批次键为“空间块 × 原型 × LOD × 材质变体”。同一原型的多个材质 primitive 仍分别绘制；阴影、材质通道也有额外绘制。示例：同树种 5,000 株、每批 128 株约 40 批，如果每原型有 2 个 primitive，主颜色约 80 次绘制；这是理想算例，非任意多树种场景的总 Draw Call 承诺。

首期两级 LOD，按包围体投影到屏幕的尺寸选择，不能只按镜头高度：

| 对象 | 近景 | 中远景 | 初始资产预算建议 |
| --- | --- | --- | --- |
| 树木 | 完整树冠、树干、叶片 MASK | 简化枝干/叶片，保留树冠覆盖与色调 | 近景约 2k–5k 三角形，中景约 300–800；取决于实际资产 |
| 灌木 | 完整低模灌木 | 简化网格 | 控制材质数和重叠叶片 |
| 草丛 | 一簇为一个实例 | 缩减可见距离，远处由已有地表承担观感 | 约 20–80 三角形/簇；不逐片草叶建实例 |

投影尺寸使用未抖动主相机，每帧只在 preUpdate 决策一次，同一批所有 pass 使用相同 LOD。采用进入/退出不同阈值及最短驻留帧抑制临界来回跳变。首期不使用逐帧变化的随机透明交叉淡化，避免增加 TAA 噪声。新 LOD 就绪后在帧边界替换，旧 LOD 在完成前继续可用；需要验收切换跳变，不能把滞回说成无缝过渡。

预算首先约束实际提交三角形、叶片填充和多 pass 成本。优先降低远处 LOD/草丛范围；不默认降低全场景分辨率或改写现有曝光、AA、阴影全局设置。首期保留所有树的位置，只改变几何细节；不靠无提示删除大批树来达标。

实例 TRS 的原始 float32 数据约 40 字节/株，5k 约 195 KiB，另加 ID；Cesium 转换后的 GPU 布局、CPU 副本、LOD、纹理和多批缓存另计。性能风险通常还包括复杂网格、多材质、叶片重叠和纹理，不能只展示这部分小缓冲大小。

## 6. 阴影、材质与 CCR 接入

### 可见性与阴影

集合隐藏才设置组 show=false。首期小规模集合保持已加载批次参与 Cesium 命令生成，由命令包围体参与主视图/光照视图剔除；不要提前仅按主相机把相机外 Model show=false 或卸载。

PoC 必须验证普通实例化 Model 的相机外命令能否进入现有 custom shadow 的原始 commandList。若不足，再为本集合增加明确的投影命令补选适配；只补当前光照范围，不能遍历场景重新执行一遍所有 primitive.update。补选不能触发二次 LOD 决策或资源创建。

首期在当前阴影覆盖范围内保留树木投影，不默认关闭远树阴影来掩盖开销；先用主视图选择的较低 LOD 降本，草丛默认不投射独立阴影。独立 shadow LOD/代理只在测得阴影瓶颈后作为后续项，并核查主颜色和阴影轮廓一致性。

实例增删、修改、批次替换、显示切换时使相关静态阴影缓存失效并 requestRender。关闭 CCR 增强后模型继续作为普通 Cesium Model 显示；集合销毁与管线销毁职责分开。

### 叶片与材质

树干使用 OPAQUE 标准 metallic-roughness PBR，叶片优先 MASK，按实际叶片几何选择 doubleSided；植被不设置成金属镜面。沿用源材质合理参数，不统一覆盖整场景粗糙度。

新资产的 alpha mip 应保留叶片覆盖率，压缩与 mip 生成后检查树冠和树影；alphaCutoff 以资产为单位标定。现有旧资产的 0.25 补丁不扩展到全部树。颜色、深度、MRT、阴影使用一致的 alpha 判定，不能出现树冠镂空但阴影整片方块。

验证实例变换后的法线、MRT 材质有效位、AO/SSR 遮挡和反射对象可见性。植被可以被道路/建筑等反射接收面看到，不要求植被本身产生强镜面反射；SSR 仍受屏幕空间可见范围限制。

TAA 验收使用静态植被，覆盖树冠 MASK 细边和 LOD 边界；新增几何/LOD 后检查历史残留。只有出现可复现残留时才增加明确的历史失效接口，不能每帧清空 TAA 历史使其失去作用。

## 7. 拟议 API 与职责

以下是待实现的接口草案，不是当前可调用 API：

```js
const plants = await CCR.createInstancedMeshCollection({
  Cesium,
  viewer,
  prototypes: [{
    id: 'oak',
    // 准备工具生成的规范静态原型；不是含 5k 株的整场景模型。
    lods: [{ url: '/trees/oak/lod0.gltf' }, { url: '/trees/oak/lod1.gltf' }]
  }],
  instances: treeInstances
  // [{ id, prototypeId, position: Cartesian3, rotation: Quaternion, scale: Cartesian3 }]
});

plants.setVisible(false);
plants.setVisible(true);
await plants.updateInstances(changes); // 合并修改，仅重建脏批次；不是每帧动画接口。
const diagnostics = plants.getDiagnostics();
plants.destroy();
```

同一入口的原型还可用 `geometry: { positions, normals, uvs, indices }` 和标准 PBR 材质定义代替 URL，生成一个静态原型再实例化。首期只接受三角网格，校验索引范围、属性数量、有限数值；纹理材质要求 UV，法线贴图还要求正确切线。法线/切线生成复用现有工具，不能随意填默认值伪造正确光照。

原型资源与实例数组加载一次、整理一次。更新使用批次 revision 丢弃迟到结果；未成功完成的新批次不替换旧批次，销毁后迟到结果立即释放。首期不承诺任意 GLB 零处理导入或复杂网格的实时编辑。

建议新增 `src/instances/`，只在 `src/index.js` 导出集合工厂。集合负责原型/批次/LOD/销毁；资产准备工具放 `scripts/`；管线现有阴影和 MRT 只在 GPU 证据指出必要时做小范围适配。Cesium 对象保持在 Vue 响应式数据之外。

诊断至少区分：总实例、已加载实例、主视图已提交实例、各 LOD 批次、主颜色/阴影/MRT 提交数、准备/加载/失败任务、集合持有资源估算、CPU 调度时间。批次内仍可能包含屏外株，“已提交”不能叫“真实可见株”。逐株拾取采用原生 instance features 的独立验证阶段，不在普通画面每帧进行拾取读回。

## 8. 实施步骤及通过条件

1. **真实资产与原生路径 PoC**：取一个实际树种和一个规范程序网格，检查叶片 alpha、子网格/材质数、尺寸和节点变换；生成 1k/5k 实例。通过条件：GPU 捕获存在实例绘制而非每株一次提交，放置/缩放/法线正确；不开 LOD 时与逐 Model 对照的画面一致。记录模型/纹理跨批复制开销。
2. **集合核心**：加入规范原型读取、空间分块、批量加载、数据更新和销毁。通过条件：5k 正常加载，10k 压力加载；一次修改只影响脏批次；取消/迟到任务不复活已销毁集合；隐藏与恢复一致。
3. **画质与两级 LOD**：接入真实树模型、alpha mip 规则、未抖动相机 LOD 和切换滞回。通过条件：近景树冠完整，远景不突然秃树或变色；慢速往返边界不持续切换；不靠降分辨率通过性能目标。
4. **CCR 多 pass 验收**：分别启用原生/自定义阴影、材质通道、AO、SSR、SMAA/TAA。通过条件：相机外树仍能向画面内投影；静态阴影缓存正确刷新；MASK/实例位置在所有通道一致；无新增重影、树冠持续抖动、shader 错误。
5. **程序化原型与交付**：同入口接入静态 TypedArray 网格，示例包含程序草簇与 GLB 来源树木；输出源码/UMD 示例、资产准备说明与性能报告。通过条件：程序网格同样走 GPU 实例化且参与已验收通道，浏览器只暴露 CCR。

PoC 如果显示大量成本来自叶片过度绘制，先修资产/LOD；如果来自 Model/批次调度，先调批次；仅在必要的实例动态更新性能仍无法达标时重新比较自定义 DrawCommand。不能跳过瓶颈证据直接重写渲染器。

## 9. 性能验收口径

建议在目标桌面机、固定 1920×1080 drawing buffer 下，以 5,000 株真实混合资产的固定校园镜头路线争取 P95 帧间隔 ≤33.3ms；16.7ms 是优化目标，尚无实测承诺。10,000 株属于上限压力档，另报结果，不能与 5k 指标混用。

对照组为同资产逐 Model、原生实例化固定 LOD、分块实例化+LOD，另保留无植被场景基线。固定显卡、浏览器、前台窗口、相机路线、太阳时间、模型版本、drawing buffer 和 CCR 配置。逐 Model 对照与原生实例化对照首先保持相同 LOD；不能把换低模带来的收益全部归给实例化。

预热后至少记录 60 秒，重复三轮，记录帧间隔 P50/P95/P99、GPU 可用计时、CPU 提交、各 pass Draw Call、三角形、首次可见/完成时间和加载长任务。冷加载与稳态分开，不能只统计加载完成后的静止天空镜头。GPU 计时不支持时标记缺失，不能用 CPU 提交时间代替。

画质路线包含树冠贴近观察、林荫路平视、斜俯视、全校园俯视、慢速跨 LOD 边界、主视锥外投影、固定镜头太阳移动。每轮验收保留截图/录屏与同配置诊断 JSON。

集合重复创建/销毁 10 次后检查对象和集合拥有的 GPU 资源释放、监听器恢复及内存是否趋于稳定；浏览器/引擎缓存另列，不能要求进程内存精确回到同一字节，也不能忽略持续增长。

- [Cesium Model](https://cesium.com/learn/cesiumjs/ref-doc/Model.html)：官方 Model 接口；具体兼容性以本地锁定 1.143 源码和 PoC 为准。
- [3D Tiles glTF 内容规范](https://github.com/CesiumGS/3d-tiles/blob/main/specification/TileFormats/glTF/README.adoc)：未来可复用的实例与实例元数据格式。
- [glTF Transform](https://gltf-transform.dev/cli) 与 [EXTMeshGPUInstancing](https://gltf-transform.dev/modules/extensions/classes/EXTMeshGPUInstancing)：资产准备工具的复用基础。

以上性能参数、API 和新增模块为设计建议；本轮只完成源码核对与方案，不代表已经实现、兼容测试通过或完成实际场景验收。
