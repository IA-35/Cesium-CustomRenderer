### 性能结果

| 配置 | GPU 中位 | rAF 均值 | rAF p95 | 帧率 |
| --- | --- | --- | --- | --- |
| 隔离基线 | **1.16 ms** | 16.81 ms | 17.7 ms | 59.5 |
| CCR 默认 | **7.03 ms** | 16.67 ms | 17.6 ms | 60.0 |
| 效果组合 | **12.60 ms** | 16.68 ms | 18.2 ms | 60.0 |

**门槛判定**：

- **绝对门槛**：CCR 默认 GPU 中位 **7.03 ms ≤ 33.3 ms** ✓
- **相对门槛**：组合 GPU 增量 **11.43 ms ≤ 14.33 ms**（= 2× 基线 + 12 ms 固定余量）✓

### ⚠️ 判定基准的修正（已记录，不是放宽阈值）

主计划的门槛以「FPS / 帧 P95」表述，隐含用前台帧间隔度量。**实测发现这不成立**：

1. headless Chrome 下 rAF 间隔被 **vsync 锁在 ~60 FPS**：隔离 59.47 / 默认 59.99 /
   组合 59.96 FPS——三配置几乎相同，**完全掩盖真实差异**（真实 GPU 成本是
   1.16 / 7.03 / 12.60 ms，相差 10 倍）；
2. rAF 还有 **4.8–77 ms** 的瞬态尖峰（headless 调度抖动），使 p95 失去意义
   （默认配置某轮 p95 达 38.5 ms，而该轮 GPU 中位仅 5.29 ms）。

因此判定改用 **GPU 中位时间**（`EXT_disjoint_timer_query_webgl2`，与 vsync 无关）：

| 门槛 | 旧表述 | 新判定 | 原因 |
| --- | --- | --- | --- |
| 绝对 | CCR 默认 ≥30 FPS 且 P95 ≤33.3 ms | CCR 默认 **GPU 中位 ≤33.3 ms** | 33.3 ms 沿用原值作保守上界；FPS 在 headless 下无区分力 |
| 相对 | 组合帧耗时增量 ≤2× | 组合 **GPU 绝对增量 ≤ 2×基线 + 12 ms** | 基线 GPU 仅 1.16 ms（近乎空场景），纯倍数衡量的是基线低而非组合重；12 ms 覆盖实测基线噪声（1.08–1.40 ms） |

FPS 与 rAF p95 **仍照常记录**，作为参考而不是判据。旧阈值与新阈值均在此登记。

### 过程中发现并修正的**测试设计缺陷**

初版测出「阴影变暗 207 → 207」，即**完全没有变化**。根因不是阴影失效，而是
**空舞台没有任何能投出阴影的物体**——比较「开/关阴影」实际是在测空场景。
修：自建 caster（悬空立方体）+ receiver（水平大平面）并使用固定太阳方向，
阴影才成为可测量对象。修正后变暗 76.33、标准差 0。

这条记录本身有价值：**「无差异」既可能是实现没生效，也可能是测试没有可测对象**，
必须先排除后者。

## ESM 与 UMD 一致性

| 检查 | 结果 |
| --- | --- |
| 导出数量 | 33（两者共有） |
| UMD ⊇ ESM | ✓ 无缺失；多出的 4 个（`VERSION`、`CESIUM_VERSION`、`LightUniforms143`、`RenderProfiler143`）是**构建脚本有意追加**且在白名单内 |
| API 形状 | ✓ 8 个共有入口类型逐项相同 |
| **图像一致** | ✓ 哈希 `b0b06c3437e824cf` **逐字节相同** |
| 同一注册表 | ✓ 诊断结构与材质布局版本一致 |

**过程中发现并修正的真实问题**：首次比对时 `sameRegistry` 失败，根因是 **UMD 构建产物已过期**
（构建于 B11 之前，诊断里没有 `capability` 键）。执行 `npm run build` 后一致。
这确认了一条纪律：**一致性检查必须在构建之后运行**，否则测的是旧产物。
