## 1. 现有雾的高度语义：`p.z` 到底是什么

**结论：现有雾运行在局部 ENU 参考系里，`p.z` 是「相对局部原点的米制高度」，
不是 `ECEF.y`。** 因此主计划「禁止 ECEF.y 当高度」这一条，对现有实现**并不成立**
（它没有犯这个错误），但存在另一个真实缺口：**局部参考系随相机移动而重建**，
所以「同一地理高度的密度响应」在相机移动后并不严格一致。

证据链（`src/environment/environmentStages.js`）：

| 环节 | 位置 | 事实 |
| --- | --- | --- |
| 射线构造 | 第 273-275 行 | `eyeRay` 经 `CCR_ENV_INVERSE_PROJECTION` 反投影，再乘 `eyeToLocal`；`origin = (eyeToLocal * vec4(0,0,0,1)).xyz` |
| 密度积分 | 第 144-145 行 | `vec3 p = origin + direction * ...`；`density = fogParams.x * exp(-(p.z - fogBaseHeight) / fogScaleHeight)` |
| 云高度 | 第 287 行 | `cameraAltitude = origin.z` |
| 云层界 | 第 203、243-247 行 | 用 `p.z` 与 `cloudParams.y/.z` 比较 |

即 `p.z` 是 `eyeToLocal` 变换后的**局部竖直轴**分量。这与 ECEF.y 无关，
所以「按椭球/局部高精度参考算高度」这一要求需要的是**把局部高度与真实椭球高度
对齐**，而不是修一个 ECEF.y 的错误用法。

**必须如实记录的差异点**（这条决定 B08 要做什么）：

- `eyeToLocal` 的局部原点如何选取，决定了 `p.z` 与真实海拔的对应关系。
  B08 需核实该原点是否随相机每帧移动；若是，则同一地点的密度响应会随相机漂移，
  这正是主计划要求「任意经纬度同一高度语义一致」要解决的问题。
- 密度公式本身是 `exp(-(h - base)/scale)` 的**逐样本求值**，
  不是解析积分；现有 `FOG_STEPS` 步长随距离平方分布（第 142 行
  `mix(start, limit, fraction*fraction)`）。主计划要求「复用 Tianjing 解析指数积分
  思想及近零 Taylor 分支」，即把基础档从数值步进改成**解析积分**。

## 2. 解析指数积分与近零 Taylor 分支

**结论：需要新增，现有实现没有解析积分。** 这是 B08 的核心新代码。

待实现的数学形式（沿视线 `o + t·d`，`t ∈ [t0, t1]`，
密度 `ρ(t) = ρ₀·exp(-(h(t) - h_b)/H)`，其中 `h(t) = o.z + t·d.z`）：

```
令 k = d.z / H
ρ(t) = ρ₀·exp(-(o.z - h_b)/H)·exp(-k·t)
∫ρ dt = ρ₀·exp(-(o.z-h_b)/H) · (exp(-k·t0) - exp(-k·t1)) / k        (k 远离 0)
```

**近零 Taylor 分支是必须的**：`k → 0`（水平视线，或 `d.z` 极小）时上式出现 `0/0`。
令 `u = k·(t1 - t0)`，则积分退化为

```
∫ρ dt = ρ₀·exp(-(o.z-h_b)/H)·exp(-k·t0)·(t1-t0)·(1 - u/2 + u²/6 - ...)
```

需要确定切换阈值。计划提到 Tianjing 的 `CalculateLineIntegralShared` 与近零分支
（R12 已定位），但本仓库内**没有 Tianjing 源码**（本项目是独立 CCR SDK），
因此该公式需按上述解析式**自行推导并用 CPU 数值积分独立对照**，
不能声称「照搬 Tianjing 实现」。这一措辞边界必须写进交付文档。

**独立的 CPU 数值积分参考**是计划明确要求的验证手段：
用足够细的定步长（如 4096 步）中点法算同一积分，与解析式对照。
这可以真正验证解析式，而不是自己验证自己。

## 3. 多视锥透明分段合并的难点

**结论：不同视锥的非线性 depth 不能直接比较，必须先统一到米制距离再合并 T/S。**
计划已指出这一点，实测确认其必要性：

- B02 的 `eyeDepth` 契约是**正米制视深度**（`MaterialChannels143` 的
  `depthContract: 'positive=known eye metres; zero=background; negative=unknown opaque occluder'`），
  多视锥下每个视锥的 near/far 不同，但 `eyeDepth` 已经是米制，可直接比较与合并。
- 合并规则（计划给定）：`T = T1·T2`（透射率相乘）、`S = S1 + T1·S2`（散射按前段透射率加权）。
  这是标准的介质分段合成，要求两段的 `t` 区间**不重叠且有序**。

**必须避免的错误**（计划点明）：不能把不同视锥的 window depth / log depth 直接比较，
也不能按「背后地面深度」给玻璃前后都上同一层雾。后者对应
`EnvironmentRenderer` 里按 `sceneDistance(uv)` 的单层积分——玻璃前后的
透明片元需要按**自身距离**读取累计介质。
