# 全量业务模型性能与动态太阳阴影修复

本轮在现有未提交工作之上继续修复，未改业务模型清单、模型精度、阴影分辨率、曝光或抗锯齿档位。

## 动态时间阴影

根因已用失败测试复现：原光空间网格以地心为原点取整，固定镜头下太阳方向微动，被约 6400 km 的坐标量放大成快速的采样相位变化。受控输入每步可变约 0.48 个纹素，实际建筑阴影会反复改变轮廓。

`LightFrustum` 改为自动从主相机建立局部网格参照，不依赖模型/地形第一次加载的中心。相机远离参照超过 5 km 时自动重定位，并保留原网格相位，避免跨区域平移造成新的跳变。直接调用的旧参数形式仍支持确定性的局部网格。太阳和投影每帧正常更新。

真实 GPU 验证使用固定相机、连续太阳方向步进，单图/三级各测两种速度。统计相邻帧 RGB 任一通道变化超过 3/255 的像素，640×420，每组 89 对帧：

| 模式 | 方向步进 | 修前每帧明显变化像素 | 修后 |
| --- | --- | ---: | ---: |
| 单图 | 1e-7 | 1286.94 | 0 |
| 单图 | 1e-5 | 1521.97 | 3.82 |
| 三级 | 1e-7 | 696.75 | 0.18 |
| 三级 | 1e-5 | 707.07 | 2.94 |

较快步进中减少超过 99.5%。仍允许太阳运动产生真实阴影边缘变化，不声称每个像素永久不变。另通过：相机跨 7 km 网格相位保持、初始 LOD 不影响最终网格、300 静止帧逐像素一致、级联过渡、MASK、画面外 caster、接地和多视锥检查。

## 性能

本次直接连接业务代理实际使用的 `http://127.0.0.1:8083/Dongda`，加载全部 13 个业务 tileset 及周边模型。默认示例的 9528 代理当时未运行，最初的空场景测量已拒绝，未计入结果。

真实负载中，基础颜色约 920 次 draw，含阴影约 1788 次 draw；其中约 868 个 caster。阴影约占 5.5 ms CPU / 6 ms GPU。

实现调整：

1. 默认单张阴影图使用对应的接收着色器，不再保留三级级联额外的 sampler、矩阵和分支。运行时切换级联数量会安全重建接收适配器。
2. 以 WeakMap 复用 caster DrawCommand 存储；每帧仍从当前源命令完整更新 count、offset、VA、材质参数、变换及 framebuffer。未缓存阴影结果，也未跳过动态投影。
3. 只有一个环境积分消费者时使用普通 uniforms，避免无共享收益的 UBO 状态查询在阴影绘制后阻塞 CPU。开启光柱/光斑、出现第二个介质消费者时恢复共享 UBO；同帧数据更新与释放验证仍通过。

1280×720、影像关闭以隔离外部服务、同一固定镜头及资产精度、RTX 3070 / Chrome、本机短采样：

| 指标 | 修前 | 修后 |
| --- | --- | --- |
| 默认 CPU 渲染中位 | 18.3–18.7 ms | 12.2 ms |
| 默认 GPU 帧中位 | 14.25–15.18 ms | 13.36–13.79 ms |
| 默认绘制次数 | 1788 | 1788 |
| 动态时间 10× CPU 中位 | 未采集同条件修前值 | 13.0 ms |
| 动态时间 10× GPU 中位 | 未采集同条件修前值 | 13.49 ms |

带诊断采样的默认/动态帧率约 56.7–57.0 FPS，关闭两项效果的同场景约 57 FPS。CPU 成本约降低三分之一。该结果说明此负载下已接近同场景的刷新上限，不是所有分辨率、显卡、模型规模下稳定 60 FPS 的承诺。
