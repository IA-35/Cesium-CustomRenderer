# 校园分阶段加载验证

2026-10-21，实际页面 `http://127.0.0.1:81/#/campus`。实现位于业务仓库 `ruoyi-ui`，车流预计算和树木上传预算位于 CCR。业务生产 dist 未重打包；CCR 已构建并同步至业务 public/js/CCR.min.js。

首屏只等待当前校区建筑 GLB、贴图、已启用 3D Tiles 以及目标视野渲染。附加任务由独立 CampusBackgroundLoader 管理，具体对象仍由 POI、植被、车流管理器负责。关闭的图层保存用户意图而不创建对象；切校区取消旧后台任务、停止旧建筑队列，返回时复用成功项并补齐缺失项。

树点位、水面、POI 已改为按需动态导入。开发环境原有 dynamic-import-node 插件及 VUE_CLI_BABEL_TRANSPILE_MODULES 都会阻止分包，已移除。通过实际开发服务器响应确认这些 JSON 模块不再内嵌到 app.js。为生效重启了原 81 端口开发服务；编译缓存备份在临时验证目录，没有删除项目资源。

## 首屏与后台顺序

最终保留 HTTP 缓存的重载中，首屏于页面时间 19.460 秒放行：70/70 建筑 ready，两组 3D Tiles 的 tilesLoaded 均为 true，树木集合数为 0、水面和车流均未创建。随后水面、两个树木集合和车流依次启动，车流于 62.128 秒就绪。601 批道路高程采样每批最多 4 点，覆盖全部 2404 个采样点。

这不是修改前后同条件的冷启动对照，不能据此宣称首屏提速比例。完整资源完成较晚，是后台工作主动让出渲染时间的取舍。具体事件与脚本请求时间见 reload-summary.json。

## 入场后卡顿追查

一次忽略 HTTP 缓存的重载仍捕获到入场后 getProgramParameter=620.9ms，以及车流准备末尾约 1 秒 CPU 长任务。进一步复用已完成的道路高程缓存，实测 TrafficSimulation 的路口冲突区域预计算连续执行 1037.9ms，确认后一处来源。

预计算现以生成器保留原计算顺序，并由 TrafficSystem 每约 4ms 让出主线程。同步调用仍保留原初始化契约。测试验证同步/分段初始化得到相同冲突区域及 200 步车辆轨迹；销毁时停止后续计算和车辆创建。

独立重建实测：11539 个计算步骤，单步最大 2.3ms，P99 0.4ms，总计算 CPU 约 1116ms；整次车辆准备墙钟时间约 9.65 秒。期间渲染帧间隔 P95 30.1ms、最大 53.1ms，没有 PerformanceObserver Long Task。此改动分散了阻塞，没有减少同等比例的总计算量。

最终整页重载的后台阶段仍记录到少量超过 50ms 的任务，最大约 123ms；不是“零长帧”。前述首次驱动编译仍是已知边界，没有通过扩大首屏门槛来掩盖它，也没有改写 Cesium 原生着色器编译路径。
