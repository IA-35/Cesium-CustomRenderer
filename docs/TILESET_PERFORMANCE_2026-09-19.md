# 分层 3D Tiles 性能复核与后续实施方案

状态：完成新一轮定位及副本实验，**未完成业务性能整改，不满足最终交付验收**。未替换业务默认资源、未修改 CCR 运行时或业务代码、未提交推送。原始 104 个分层 GLB 的 SHA-256 已逐个复核，均未改变。

## 1. 本轮实际测试范围

- RTX 3070，Chrome headless，1280×720、DPR=1，使用当前业务服务实际的 Cesium 核心补丁与 CCR 包。
- 挂载真实 MainMap 组件，加载当前南湖清单 13 组模型及原有背景资源；业务 API 使用既有测试夹具。因此不等于登录后的全部业务数据、所有展开楼层或双校区同时驻留验收。
- 固定时间、相机中心、俯角、距离和旋转轨迹；每轮 180 帧，采集 Scene.render CPU、异步 GPU timer、实际 WebGL draw 和展开实例后的三角形提交数。
- 原始／候选引擎哈希、CCR 哈希和画面选项完全相同。主表采用无 CPU Profiler 的第二次同轨迹采样；原始与候选串行运行，仍属于短测。
- 16GB / 移动 RTX 3060 未连接本机，**没有笔记本实测**。本轮没有采集进程峰值内存或专用显存，不能把资产逻辑统计替代它们。

## 2. 瓶颈与证据

原始 10 组分层建筑包含 104 个 GLB、592 个 primitive，约 687 万基础三角形，没有有几何内容的粗模替代层。提高 SSE 不能产生缺失的 LOD。

综合楼 177 个 primitive 只对应 30 种不同的材质状态；实验楼一期 107 个对应 29 种。跨楼层使用相同材质却分散在不同 GLB，主画面与阴影重复提交是重要开销。

诊断移除分层建筑时，实际绘制从约 1848 降到 677，CPU 中位从约 20ms 降到 9.7ms（此组开启 CPU Profiler，只作归因）。Model.update 的合计中位约 0.8ms；不支持把本次稳定旋转问题主要归咎于瓦片遍历。移除模型只是负对照，不是实施方案。

树木保留在正式候选测试中，植被实例化分支未修改。去掉树木后的稳态测量仍有约 1822 次 draw，分层提交问题依然存在。

## 3. 已完成的副本实验

新增独立离线工具 `tools/tileset-overview/`，复用 glTF Transform、Draco 解码及 Meshoptimizer，不把资产处理放入浏览器运行时。

1. 按单栋建筑合并兼容材质，统一世界坐标和 glTF Y/Z-up 变换。
2. 重编号顶点 feature ID，保留原始字符串属性，附加 `ccrSource`、`ccrFloor` 追溯来源。原始 `id` 在不同文件间存在重复，后续交互必须使用建筑身份 + 来源 + feature 的复合键，不能只用 `id`。
3. 支持 OPAQUE/MASK；拒绝 BLEND、动画、骨骼、实例化、未知扩展、不支持的元数据和已有内容 LOD，避免默默破坏语义。
4. `--compact` 使用 16 位位置／法线和 Meshopt 编码，不量化 UV、颜色或 feature ID。它与不量化的合批副本分别记录；有精度变化，尚未完成近景画质验收。
5. 不覆盖输入或既有输出；不生成自动楼层切换，不把输出当作原分层 tileset 的直接替代品。

10 组分层建筑从 **592 → 243 primitive**，三角形仍为 **6,869,559**。压缩副本文件合计从原始 **207.67 MiB → 141.92 MiB**，传输体积下降不等于驻留内存下降。

| 第二次旋转采样 | 原始分层模型 | 合批 + 紧凑副本 |
| --- | ---: | ---: |
| 实际绘制中位 / 帧 | 1853 | 1161 |
| CPU 中位 | 17.7ms | 12.5ms |
| CPU P95 | 22.0ms | 14.6ms |
| GPU 中位 | 14.64ms | 12.53ms |
| 帧间隔 P95 | 23.6ms | 17.6ms |
| 平均帧率 | 51.52 | 57.84 |
| 13 组模型资产逻辑驻留量 | 841.93 MiB | 888.06 MiB |

绘制约减少 37%，CPU 中位约减少 29%，GPU 中位约减少 14%。平均 57.84 不是稳定 60 FPS 的验收结果；1280×720 也不能外推到 1080p、2K、高 DPR 或移动显卡。

**内存门槛未通过**：副本逻辑驻留量反而增加约 46.13 MiB。整栋合并也会降低原有空间剔除和局部卸载粒度。因此不能直接发布这个副本，更不能把合并全部几何当作 16GB 笔记本问题的最终答案。

## 4. 验证与未通过的实验

- 工具 3 项测试通过：兼容材质合并、旋转/轴向转换后的世界坐标、元数据和 feature ID、紧凑存储、拒绝覆盖输出、拒绝透明和未知扩展、Draco 非法索引别名兼容。
- 真实源文件中部分索引 accessor 错把 Draco 压缩块当作普通 bufferView。工具仅在内存副本中移除这个别名，仍用必需的 Draco 解码结果；原文件不变。
- 真实 GPU 候选有完整模型负载，三角形提交没有下降为“空场景”；9 栋可见分层建筑实际拾取返回原始属性及楼层来源。
- 原始与候选截图已检查；没有完成跨启动严格像素一致性门槛，也没有验证全套 hover、轮廓、展开、收起和楼层资源切换。不能将拾取属性成功写成业务交互全部通过。
- 第一份 `overview-prototype` 因顶层 geometricError=0 导致内容未加载，**完全排除其性能数值**。已修正顶层入口误差并补“每组必须有已加载内容”的门槛。
- `overview-valid` 在大文件通过浏览器协议传输时浏览器提前关闭，没有结果，不作为证据；改为 HTTP 服务传输后完成，未认定关闭的确切原因。
- 第一轮 `baseline` 的 no-trees 子项恢复资源尚未稳定，排除；正式脚本已逐子项等待可见资源请求和处理队列稳定。
- 原始 JSON、截图和生成副本保留在本机 `docs/verification/tiles-cost/`；可携带摘要见同名 `.json`。无效结果没有被写成成功结论。

## 5. 正式整改顺序

### P1：制作有真实 LOD 的建筑总览资源

以本轮合批工具为起点，产出“按建筑或有空间边界的建筑分块”的外壳，而非整校园一个大网格。继续保留原始分层资源。

- 近景保留外壳外观和细节；中远景生成真正的简化几何。简化必须约束轮廓、门窗、材质边界和 feature 边界，并记录世界空间误差。
- 使用原生 REPLACE 层级和真实 geometricError，禁止仅改 JSON 声称实现 LOD。
- 整栋过大时按空间分块，避免当前实验整栋驻留带来的内存上升；同源纹理复用现有核心补丁。
- 先用综合楼和实验楼一期完成近、中、远三距离对照，再扩展到其余建筑。目标是在降低 draw 的同时降低几何驻留和 GPU 耗时；内存不降的候选不得接入默认场景。

### P2：总览与楼层操作分开加载

业务默认加载轻量总览资源。hover、轮廓、建筑点击直接作用于总览；不因为相机移动禁止 hover。

- 进入楼层操作时，按建筑身份加载该栋原始分层数据；新资源可见且就绪后再切换，避免空白或重叠。
- 展开、移动楼层、室内选择仍使用原始 tile 层级与变换，不能对合并网格伪造楼层动画。
- 退出时恢复总览；详情资源短时间复用，超出预算后卸载。快速切换、取消加载、销毁、选择对象重绑定必须有回归。
- 复用 `MainMapView.vue` 既有楼层运行状态、资源管理器和 `TilesetMemoryBudget`；只增加总览/详情资源切换边界，不另外建立一套业务资源管理器。

### P3：把内存目标变成可执行的资源集合预算

当前 768 MiB 预算会保护当前 pass 必需资源，而且运动/加载阶段恢复各 tileset 余量；它是软目标。对无 LOD 的全量可见集合，不能靠强制驱逐把内存压下去，否则会不断卸载、解码和上传。

- 先通过 P1/P2 缩小“当前必须显示”的集合，再以场景总预算管理详细资源。
- 分别测 JS/ArrayBuffer、浏览器多进程私有内存、专用显存及加载峰值；不要只看 GLB 文件大小或 tileset.totalMemoryUsageInBytes。
- 校区切换、长距离旋转、反复进入不同楼层之后，资源必须回落，不能随操作单调增长。

### P4：性能与业务共同验收

- 相同模型清单、分辨率、DPR、时间、相机轨迹和画面开关进行 A/B/A；每组必须验证内容和交互，不能以漏模型获得收益。
- 桌面与目标笔记本分别跑冷启动、预热旋转、近景、楼层展开/退出、多楼切换。60 FPS 对应 16.7ms 帧预算，CPU/GPU 应留余量，不能只看静止 FPS 计数器。
- 正式分辨率下帧时间、内存峰值、释放回落及近景画质全部满足约定门槛后再替换业务默认地址。

## 6. 复用边界

- CCR 负责画质和必要渲染通道；Cesium 核心补丁继续负责有预算的加载、编译和纹理共享。
- 离线资产工具负责合批、简化、压缩及 feature 映射；业务负责何时进入/退出楼层详情。
- 不接入未完成的 `src/tileset/TilesetOptimizer143.js`：当前 VisualPipeline 没有使用它，其中卸载包装只是计数，不是已实现的分帧回收，不能当作现成性能修复。
- 本轮没有修改植被工作、业务 hover 策略、渲染效果配置或已提交 SDK。
