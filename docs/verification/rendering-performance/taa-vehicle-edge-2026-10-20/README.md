# 道路车辆周围 TAA 闪烁修复

2026-10-20。用户确认目标是道路车辆。实际页面为 `http://127.0.0.1:81/#/campus`，TAA 开启。

## 根因与范围

TrafficSimulation 以 STEP=0.05 s 推进，渲染帧之间存在“位置更新 → 位置不变 → 位置不变”的节奏。TaaMotion143 原本仅在刚性对象从静止重新运动、且上一帧没有运动标记时，清除旧位置的包围矩形历史。车辆每个模拟 tick 都重新满足这个条件，导致车旁未被车身覆盖的道路像素反复丢弃累积，形成闪烁环带。

实际车流加载后确认：60 个 Model、240 个车辆 primitive 均为 OPAQUE、无实例化，使用已支持的刚性 motion 路径。实测更新帧曾出现约 236 次矩形 previousFootprints，不是单纯一两个像素的深度容差问题。

## 修改

`src/antialiasing/TaaMotion143.js`：在已有刚性模型程序和 framebuffer 上，使用上一帧 modelMatrix 再绘制一次旧车辆网格，仅写运动纹理 alpha=-1；保留材质 discard 和当前深度测试，当前车身运动向量随后正常写入。

- 旧位置只按真实网格轮廓拒绝历史，周围背景保留累积。
- 复用已有 motion shader、纹理、native depth alias 和 RenderItemExecutor，不新增历史纹理或全画面失效。
- alpha-only render state 缓存复用，并随原记录淘汰和销毁时释放。
- 车辆着色、几何、车流速度、50 ms 模拟节奏、静止 TAA 权重和高亮颜色变化跟踪均保持。
- 无精确 motion 支持的内容/静止对象销毁等原有保守兜底没有扩大修改；不宣称修复了任意蒙皮、变形或自定义顶点模型。

## 量化验证

1. 复用仓库 taa-r186-fixture，在静止细线背景上让刚性物体每 3 个渲染帧移动一次。统计物体真实投影轮廓外 2.5–8 px 环带；该区域不应反复丢弃静态历史。每例 64 帧，汇总舍弃前 8 帧。
2. 真实业务页暂停车流以固定其他物体，选择 `campus-car-1`，相机固定在车辆附近；让该车按相同分步节奏移动。对同一实例依次执行原 capture 和修改后 capture，统计车辆投影包围球外 2.5–8 px 的背景环带。结束后还原捕获方法、车辆矩阵、相机、渲染循环并恢复车流播放。

| 对照 | 修复前平均帧间 RGB 最大分量差 | 修复后 | 变化 |
| --- | ---: | ---: | ---: |
| 分步刚性物体＋细线背景 | 0.02833 | 0.000635 | 降低约 97.8% |
| 真实车辆＋道路背景 | 0.004274 | 0.0000321 | 降低约 99.2% |

真实车辆环带的最大帧间变化从 0.2171 降至 0.00739。指标来自线性 HDR 像素差，不是 FPS、整图质量分数或“所有动态边缘完全无闪烁”的证明。该车更新帧仍为 4 个旧轮廓 draw + 4 个当前 motion draw，数量没有增加；变化的是遮罩覆盖范围。

独立测试也保留不支持的 custom-fragment 模型作为范围对照：它仍走原保守兜底，指标未改善。用户所指道路车辆已确认不走该路径。

## 回归与发布验证

- 38 项定向测试通过：上一帧矩阵、仅 alpha 写入、前景深度遮挡、分步运动状态复用、资源淘汰/销毁、高亮局部失效和 TAA resolve 契约。
- 现有真实 GPU 回归通过：拾取不重置历史，静止亚像素覆盖保留，远处运动不干扰静态细节，物体移走/消失不保留车影。旧回归曾要求整个包围矩形逐像素等于当前帧，正好会强制恢复本次闪烁缺陷；已改为只对含离开物体颜色的像素检查旧 RGB 拒绝，并要求覆盖 >100 个像素。中心揭露的严格误差检查仍保留。
- 构建成功并同步业务 `public/js/CCR.min.js`，SHA-256：`a5fa5a33e3457862febbf798a86f35aee46e75601f7269980133818408be98cc`。
- 刷新加载新版并恢复真实车流后，60 辆车 ready/playing。120 帧记录 11792 次旧网格轮廓绘制、12736 次当前车辆 motion 绘制；矩形清除 0，motion errors=0，failed=false。historyAge 从 3846 增至 3966，reset 计数保持 78，appearanceChanges 诊断仍在。
- 一次较早的 120 帧检查出现 5 次 finish 阶段保守矩形失效（资源消失/不可跟踪内容允许走该兜底），因此不能要求所有场景永远零矩形。最终验证同时区分 capture 内的旧车辆路径和 finish 兜底，避免把其他资源生命周期事件当成车辆失败。

before-stepped.json / after-stepped.json：分步物体；business.json：同实例道路车辆对照；deployed.json：新版真实车流；unit-tests.txt；regressions.json：GPU 回归。check-stepped-edge.cjs / check-business-edge.cjs / check-deployed.cjs 是本机探针，复跑前核对 CDP、端口、页面和输出目录。

本轮没有新增车辆资产，也没有改变业务道路和车流数据。验证覆盖静止相机下的分步车辆与采样背景环带；未穷举所有距离、相机运动、阴影变化和其他硬件。此次像素读回仅用于验证，已从正常运行路径移除，不能将这些测量作为性能基准。
