# 开启车流帧率下降：测量与优化

2026-10-20。实际页面 `http://127.0.0.1:81/#/campus`，1264×805，TAA，阴影 2048、更新间隔 3、shadowStatic=true，60 辆车。车流关闭、显示暂停、播放使用同一相机。鼠标移出场景交互区域；没有 CPU Profiler、同步像素读回参与性能采样。

## 定位结果

每组预热 90 帧后记录 240 帧，直接计数 GL draw，包围 Scene.render / 模拟推进 / motion capture / motion finish / 阴影提交。帧间隔来自相邻 Scene.render 开始时刻，包含刷新调度，不等同于显示器实际呈现时间。

- 关闭车流：CPU 平均约 14.1 ms，draw 中位数 885。
- 显示但暂停：CPU 平均约 19.2 ms，draw 中位数 1125。60 辆车每辆 4 个 primitive，仅颜色渲染就增加 240 次提交。
- 正常播放：CPU 平均约 26.6 ms；模拟平均 3.0 ms，更新帧 P95 6.4 ms；motion capture 平均 4.2 ms，shadow 平均 3.3 ms。运动、旧轮廓、阴影都重复提交各部件，draw P95 2353。
- 临时省略旧轮廓的对照没有恢复整体帧率，因此不能把问题仅归于上一轮防闪烁修复；该实验结束后恢复原逻辑，未作为生产降质方案。

## 实现

1. `TrafficSimulation.js`：同一个 50 ms 模拟步内缓存车辆碰撞姿态，route、distance、尺寸变化时重算。检查下一条路的假设位置、碰撞回退仍使用正确位置；下个模拟步清空缓存。避免每对车辆都重新采样道路并分配多个向量，保留完整碰撞安全检查。
2. `TaaMotion143.js`：主颜色绘制时收集运动任务，完成 opaque depth 后，在 TAA resolve 前统一提交；保存原 framebuffer、viewport 和每个 primitive 的矩阵/覆盖参数，单次保存和恢复 GL target/渲染 pass。仍绘制精确旧车辆轮廓；不恢复矩形失效，不增加历史纹理。
3. `prepare-traffic-demo.cjs` 与三款车辆 GLB：将车身/车窗/轮胎/车灯合并为一个 primitive。位置、法线、索引拓扑保持；线性基色写入浮点 COLOR_0。金属度/粗糙度写入 4×1 常量 PNG 的 B/G 通道，字节为参数×300，采样后乘 .85（255/300），精确恢复原参数；采样用 NEAREST，无跨材质插值。每车 4 次颜色提交降为 1 次，运动及阴影同步减少。

生成器新增 `--cars-only`，仅更新三款车，避免重写道路或交通网络。原始三款资产备份在 evidence/original-models；生成后每款约 11.8 KB（原约 8.9 KB），额外顶点属性和 4 像素材质数据换取提交减少。没有减少车辆数量、改变速度/模拟步长、关闭车辆阴影或降低观察分辨率。

## 业务页最终结果

前后 canvas、AA、阴影尺寸和更新间隔一致；各组内 Viewer 身份未变化。最终版重载后重新等待建筑和 60 辆车完成加载。其他应用仍共享 GPU，因此报告实际短测结果，不承诺固定 FPS。

| 车流状态 | 原版平均帧间隔 | 新版平均帧间隔 | 原版 P95 | 新版 P95 |
| --- | ---: | ---: | ---: | ---: |
| 关闭 | 16.68 ms | 17.02 ms | 18.5 ms | 21.5 ms |
| 显示但暂停 | 19.66 ms | 17.31 ms | 25.9 ms | 22.5 ms |
| 播放 | 27.12 ms | 19.37 ms | 40.3 ms | 27.6 ms |
| 播放重复组 | 27.45 ms | 19.08 ms | 41.9 ms | 28.8 ms |

播放短测对应约 37 → 52 FPS（1000/平均帧间隔），CPU 平均约 26.6 → 18.8 ms，draw P95 2353 → 1642，motion draw 峰值约 480 → 120。模拟平均约 3.0 → 0.28–0.32 ms。

中间仅缓存模拟/延后 motion、尚未合并车辆的同实例实验：模拟平均已降至约 .34 ms，但整帧仍约 25 ms。最终提升主要还需要 4→1 的车辆 primitive 合并，不能把最终收益全归于 framebuffer 批量提交。

## 正确性验证

- 77 项定向测试通过，覆盖跟车/路口/生成与回退、不缓存过期姿态、与无缓存模拟轨迹一致、模型三角形/法线/颜色/PBR 数值一致、motion 合并提交时 framebuffer/viewport/pass 隔离和资源生命周期。
- 现有真实 GPU TAA 回归通过：拾取连续性、静态细线、物体离开后的历史拒绝、远处运动不破坏静态覆盖。
- 业务近景直接对照原版四部件 car-blue 与合并版：相同相机、光照、暂停状态，200×200 ROI 线性 HDR 平均差 0.0000138，最大差 0.00525；两者 TAA 重新收敛后比较。不是全资产所有光照条件的逐像素等价证明。
- 合并车辆重新做分步移动边缘检查：背景环带平均帧间变化约 0.0000215，最大 0.00591；更新帧只需 1 次旧轮廓 + 1 次当前运动绘制，无 motion 错误。保留此前对车辆周围闪烁的修复。
- 最终运行状态：60 Model ready、60 个车辆 primitive、playing=true、visible=true、所有车辆 ShadowMode.ENABLED，motion.failed=false、pendingDraws=0。
- 构建成功，SDK 与业务 public/js/CCR.min.js 均为 SHA-256 `736d3c5d248c399e33c2ebfc7812554682af6d1b99f2c3485589f0419f8e8004`；三款车已同步到业务 public/traffic-assets。业务 dist 未重新打包。
