# 业务轮廓与阴影性能优化

目标：按用户确认的顺序降低轮廓整场景 ID 重绘和逐帧阴影提交成本；检查实际 3D Tiles 结构能否进一步减负。保持当前模型精度、动态阴影、MASK、选中遮挡和生命周期语义。

1. 复用 native silhouette 与已有 opaque depth：在单视锥、单采样、普通不透明 globe 路径复制主画面深度到 ID framebuffer；仅绘制选中 Model/3D Tiles 内容及必须保留的透明/特殊深度命令。未知选中类型、复杂深度路径回退原生 ID 绘制。逐帧解析内容归属，不缓存异步 tile 结果。
   - 先测选中归属、未知对象回退、非渲染 picking 不变、外部 hook 保留。
   - GPU 比较原生/优化的轮廓输出，含遮挡、MASK、透明、镜头变化、MSAA 回退。
2. 阴影候选及光空间剔除保持不变；仅重排已生成的 opaque/MASK caster，按 program/state/vertexArray 分组，减少状态切换。等深度深度写入应可交换；比较重排前后 depth 与最终图像，动态太阳仍每帧更新。
3. 收集 13 个业务 tileset 的 LOD/误差结构、三角形、纹理与命令负载；若无可靠的通用运行时减负路径，明确区分已优化重复提交与仍需离线处理的模型负载，不通过调高 SSE 或删除模型虚报收益。
4. 更新 SDK，同步业务 public 包，校验服务实际响应。固定相机/时间/分辨率/AA，做轮廓 A/B/A 与阴影开销检查。保留现有修改，不自动提交。
